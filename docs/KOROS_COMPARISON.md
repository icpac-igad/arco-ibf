# Differences from koros-arco-ibf

This document details what was ported from `koros-arco-ibf`, what was changed, and what is not yet implemented.

## Architecture Comparison

| Aspect | koros-arco-ibf | arco-ibf (this repo) |
|--------|---------------|---------------------|
| **Framework** | Next.js + Tailwind CSS | Next.js + USWDS/SCSS |
| **Backend** | Docker stack (PostGIS + Django/Wagtail + FastAPI/TiPG + titiler) | Single FastAPI reading parquet files |
| **Data source** | PostGIS database + Wagtail CMS | EM-DAT parquet files (ea-impact-events) |
| **Map library** | MapLibre GL (vector tiles from TiPG) | Pure D3.js (static TopoJSON) |
| **MDX rendering** | next-mdx-remote v6 | next-mdx-remote v6 (same) |
| **State management** | Local state in monolithic component | PipelineProvider context with URL sync |
| **Boundaries** | Vector tiles via TiPG API | Static `icpac_adm1v3.json` (227 Admin1 regions) |

## What Was Ported from koros-arco-ibf

### MDX Rendering Pattern
- **`next-mdx-remote`** serialize + `MDXRemote` client rendering
- **`gray-matter`** for frontmatter parsing
- Same library versions (`next-mdx-remote@^6.0.0`, `gray-matter@^4.0.3`)

### MDX Components (adapted, not copied)
Koros components in `frontend/src/components/storyline/story-ui.tsx`:
- `CountryHeader` → ported to `app/components/mdx/event-components.tsx` (uses inline styles instead of Tailwind)
- `ImpactStats` → ported (same structure, inline styles)
- `Hero`, `StatGrid`, `Stat`, `Block`, `Prose` → ported

### Color Scales
Koros `frontend/src/lib/colors.ts`:
- Hazard-specific D3 threshold scales (warm reds for drought, cool blues for flood)
- Ported to `app/lib/colors.ts` with same color values

### Content Pattern
Koros `frontend/content/stories/east-africa-drought.mdx`:
- 2 hand-curated MDX storylines (drought + flood), each covering ~11 countries
- Uses `<Storyline>`, `<Chapter>` scroll-driven components with MapLibre

This repo `app/content/events/{drought,flood}/*.mdx`:
- 448 auto-generated per-event MDX files from parquet data
- Uses `<CountryHeader>`, `<ImpactStats>` (no scroll-driven map)
- Generated by `generate_event_mdx.py`

## What Is Different

### 1. No MapLibre / TiPG dependency
Koros uses MapLibre GL with vector tiles served by TiPG for:
- Storyline sticky map with scroll-triggered fly-to animations
- Choropleth map with dynamic boundary highlighting
- Basemap switching (satellite, dark, streets, OSM)

This repo uses **pure D3.js** with static TopoJSON for the choropleth. No interactive basemap, no scroll-driven map animations.

### 2. No Docker stack required
Koros requires 5 Docker services (PostGIS, Django/Wagtail, FastAPI, TiPG, titiler). This repo needs only:
- `uvicorn app:app --port 8000` (FastAPI reading parquet)
- `npx next dev --port 3000` (Next.js)

### 3. Pipeline architecture vs flat view
Koros has a **flat single-page view**: hazard toggle → compare maps → calendar → storylines (all visible at once).

This repo has a **4-stage pipeline** (only stage 1 active):
- `?stage=events` — calendar + choropleth + MDX event detail
- `?stage=storylines` — disabled (coming soon)
- `?stage=crma` — disabled
- `?stage=ibf` — disabled

### 4. Per-event MDX vs curated storylines
Koros: 2 comprehensive MDX files with `<Storyline>` / `<Chapter>` scroll-driven narratives covering all countries for a hazard.

This repo: 448 individual MDX files, one per EM-DAT event (e.g., `2021-9546-ETH.mdx`). Loaded on-demand when a calendar cell is clicked.

### 5. MDX loading strategy
Koros: **Build-time** — `loadStories()` in server component serializes all MDX at page load, passes as props.

This repo: **On-demand** — Next.js API route (`/api/event-mdx`) serializes a single MDX file when requested by the client after calendar click.

### 6. Styling approach
Koros: Tailwind CSS utility classes throughout.

This repo: USWDS design system + SCSS (`dashboard.scss`). MDX components use inline styles to avoid USWDS/Tailwind conflicts.

## What Is NOT Implemented (from koros)

| Feature | koros Location | Status |
|---------|---------------|--------|
| Scroll-driven `<Storyline>` + `<Chapter>` | `story-map.tsx` | Not ported — requires MapLibre |
| MapLibre interactive map | `choropleth-map.tsx`, `story-map.tsx` | Using D3 choropleth instead |
| Vector tile boundaries | TiPG Docker service | Using static TopoJSON |
| Basemap switching | `story-map.tsx` BASEMAPS | Not needed (D3 map) |
| Country bbox fly-to | `geo-api.ts` `getCountryBbox()` | Not ported |
| Wagtail CMS integration | `events/models.py` | Not needed (parquet data) |
| Django admin for events | `events/wagtail_hooks.py` | Not needed |
| CI/CD pipeline | `.github/workflows/ci.yml` | Not ported |
| Static event data | `lib/static-events.ts` | Replaced by parquet-based API |
| Dual calendar view (compare) | `crma-dashboard.tsx` default view | Single calendar per hazard |
